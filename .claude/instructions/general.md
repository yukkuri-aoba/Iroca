# 基本ルール

## 他のセッションとの連絡（作業開始時）
- このプロジェクトでは複数の Claude セッションが並行して動いていることが多い。**作業に取りかかる前に `ListAgents` で動いているセッションを確かめ、関係しそうな相手には `SendMessage` で連絡する**。ユーザーに言われるまで待たない。
- 関係しそうな相手: 同じファイル・同じ worktree・同じブランチを触る、重いテスト（品質ゲート・abcheck など）で CPU やメモリを取り合う、`visual_review.py` の snapshot/approve を使う、相手の結果（採否・計測値）に依存する、など。
- 伝えること: 何をどこで（ブランチ・worktree・主なファイル）始めるか、相手とぶつかりそうな点、相手に聞きたいこと。短く、日本語で。
- 関係する相手がいなければ連絡は不要（確かめたことだけ一言報告すればよい）。作業中に衝突しそうになったときや、相手に影響する結果が出たときも連絡する。

## 一時ファイルの後始末
- セッションの scratchpad（`%TEMP%\claude\...\<セッション>\scratchpad`）は誰も掃除しない。中間の画像・raw・npy・
  出力の山は、結果を dev_safe に残したら**そのセッションのうちに消す**（2026-10-22 に 21GB 溜まっていた）。
- 後で使い回す環境（競合の一時 Unity プロジェクトなど）は **`%TEMP%` の外へ移してから**、どこに残したかをメモに書く。
  この PC はストレージセンサーが有効で、`%TEMP%` の中の 7 日以上更新されていないファイルを消す。scratchpad も
  `%TEMP%` の中なので、残したつもりの Unity プロジェクトが Assets・ProjectSettings を失って Library だけになっていた
  （2026-10-22 に確認）。コピーで元の日時が残るファイル（写した DLL・展開した素材）は作った直後でも消されうる。
- `%TEMP%` 直下に作った一時フォルダ（`iroca-*` など）も同じ。worktree の片付けは git モジュールに書いた。

## UI 実装方針
- Unity Editor UI に新しい操作要素（ボタン・スライダー・トグル・入力フィールド等）を追加するときは、**必ずツールチップを付ける**（`GUIContent(..., tooltip)` など）。操作の意味と効果が UI だけで伝わるようにするため。
- 既存要素の文言・レイアウトを変えるだけのときは対象外。

## 公開リポに被写体名を書かない
- 本体リポは公開されている。テストに使う被写体（アバター名・`<avatar>-<part>` 形式の被写体 ID）を、コードコメント・`tools/`・`docs/`（販促とマニュアルを除く）・コミットメッセージに書かない。「白い布」「アトラス被写体」のように素材や性質で書く。
- 被写体の一覧は `dev_safe/Tests/subjects.json` が正。計測の根拠を被写体名つきで残したいときは dev_safe 側に書く。
