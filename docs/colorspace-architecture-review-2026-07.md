# 二色空間アーキテクチャの正当性レビュー — 選択=HSV / 再着色=OkLab（2026-07-11）

対象: `Code/Core/ColorZone.Match.cs`（選択マッチング）／ `Code/Core/PixelProcessor.Recolor.cs`・`PixelProcessor.ColorSpace.cs`（再着色）
関連: [`oklab_matching_conclusion.md`](oklab_matching_conclusion.md)（選択を OKLab 化する実験の不採用記録）／ [`recolor_design_rationale.md`](recolor_design_rationale.md)（再着色中核の設計根拠）／ [`image_processing_math_review_2026-06-10.md`](image_processing_math_review_2026-06-10.md)（数学検証）

本書は「ピクセル選択に HSV、再着色に OkLab という**使い分けそのもの**は色空間の特性から見て正当か」という問いに答えるレビュー記録である。既存 2 ドキュメントが片側ずつ（選択= HSV 維持の理由／再着色= OkLab 採用の理由）を扱うのに対し、本書は**非対称な分業自体**を対象にする。

---

## 1. 結論

**正当である。** 選択と再着色は色空間に対して**相反する要件**を課す別問題であり、単一の標準色空間では両方を満たせない。

- **選択**は「この画素はサンプルと同じ素材か」という**同一性判定**の問題。必要なのは*陰影に対する不変量*。HSV の S（比率彩度）は乗算的な暗化に対して厳密に不変で、この要件をネイティブに満たす。
- **再着色**は「新しい画素はどう見えるべきか」という**外観合成**の問題。必要なのは*知覚均一性*（色相を変えても明度・陰影の見えが保たれること）。OkLab はこれをネイティブに満たし、HSV の V は満たさない。
- この 2 性質（陰影不変な彩度 vs 知覚均一な絶対量）は**同一の色空間内で両立しない**（§4）。よって「選択= HSV / 再着色= OkLab」は妥協ではなく、要件の非対称性に対する構造的に正しい対応である。
- 両方向の裏付けが揃っている: 選択の OKLab 化は実測 A/B で不採用確定（勝ち被写体ゼロ・costume recall 0.997→0.609 崩壊）、再着色の HSV 時代はリング・brown 化・ベタ塗りが実害として記録され OkLab 移行（f69e423）で構造解消。**片方向だけでなく、逆向きの構成が両方とも実際に試されて失敗している**点が、この分業の強い証拠になっている。

ただし「選択= HSV」は単純化であり、実態は **HSV + RGB ハイブリッド**である（§2）。また分業には無料でないコストが数点あり、§6 に留意点として記録する。

## 3. 色空間の特性整理（レビューの軸）

このドメイン（手描き VRChat アバターテクスチャ）の支配的構造は「**飽和したベース色 × 乗算的な明度シェーディング**」である。これを軸に各空間の性質を並べる。

### 3.1 乗算シェーディングに対する挙動

エンコード済み RGB を k 倍（0<k≤1、暗化）したとき:

- **HSV**: `V = max(R,G,B)` → kV。`S = (max−min)/max` → **厳密に不変**。`H` → **厳密に不変**。
  つまり HSV は色を「陰影不変な素材属性 (H, S)」×「陰影軸 (V)」へ**そのまま因数分解**する。これは安価な albedo/shading 分離であり、手描きシェーディング（ペイントソフト上の乗算暗化）と仮定が一致する。
- **OkLab**: 線形 RGB を f 倍 → LMS が f 倍 → 立方根で l′,m′,s′ が f^(1/3) 倍 → L, a, b は（その線形結合なので）**すべて f^(1/3) 倍**。したがって chroma `C = √(a²+b²)` は**陰影とともに縮む**。不変なのは比 `C/L` のみ。
- （エンコードの注意: 手描き陰影はエンコード空間の乗算に近く、HSV S の不変性はそこで厳密。OkLab 側はリニア光の乗算に対する性質だが、エンコード k 倍 ≈ リニア k^2.4 倍 → L, C とも ≈ k^0.8 倍で「C は縮む・C/L は不変」という対比はどちらの仮定でも保たれる。）

### 3.2 知覚均一性

- **HSV**: V = max は明度の粗い代理にすぎない。**同じ V でも色相によって知覚明度が大きく違う**（純黄 V=1 は明るく、純青 V=1 は暗い）。S も知覚彩度と非線形。→ 色相を変えつつ S/V を保持すると、知覚上は明度構造が崩れる（リング・白部サイズ変化・ベタ塗りの根本原因。`PixelProcessor.ColorSpace.cs:17-21` のコメントに記録）。
- **OkLab**: 知覚均等設計。等 ΔL ≈ 等知覚明度差、色相角が知覚色相にほぼ線形、無彩軸で特異点なし。→ 明度リマップの単調性が**知覚上の**単調性として保たれる。

### 3.3 特異点・退化

- **HSV**: S→0 で Hue が未定義（角度の特異点）。暗部（V→0）では H/S がノイズで暴れる。
- **OkLab**: 特異点なし。ただし C→0 で色相角は同様に不安定（これは極座標表現に共通で、OkLab 固有の優位は「距離計算がデカルト (a,b) で完結する」こと）。

### 3.4 まとめ表

| 性質 | HSV (H,S) | HSV (V) | OkLab (L,C) | OkLab (C/L) | RGB |
|---|---|---|---|---|---|
| 乗算シェーディング不変 | **○（厳密）** | ×（＝陰影軸） | ×（f^(1/3) で縮む） | **○** | × |
| 知覚均一性 | × | × | **○** | —（比率量） | × |
| 特異点 | S≈0 で H 退化 | — | なし | L≈0 で発散 | なし |
| 変換コスト | 低 | 低 | 中（cbrt×3、LUT 化済み） | 中 | ゼロ |

**要点: 「陰影不変な彩度」と「知覚均一な絶対量」は同じ座標系では両立しない。** 陰影不変にするには比率（S や C/L）を取るしかなく、比率を取った瞬間その量は知覚距離の公理を失う。逆に知覚均一な C は絶対量である以上、陰影で必ず縮む。これが本アーキテクチャの非対称性の理論的な根拠である。

## 4. なぜ「選択= HSV（ハイブリッド）」が正当か

選択は分類問題であり、距離式に求められるのは「**同素材の陰影バリエーションを近く、別素材を遠く**」写すこと。§3.1 のとおり、飽和ベース色 + V シェーディングという支配的スタイルでは HSV の (H, S) が**厳密な不変量**としてこれを満たす。濃紺の衣装は深い影でも S≈1.0 を保ち、彩度ゲート・距離項のどちらでも「同じ素材」であり続ける。

これは理屈だけでなく実測で確定している（詳細は `oklab_matching_conclusion.md`）:

- OKLab 絶対 chroma の選択距離は costume の recall を 0.997→0.609 に崩壊させた（飽和青の深い影が「別素材」判定される）。
- 修正には明度正規化彩度 C/L の導入が必要で、それは**HSV の S を OkLab 上に再構築することに等しい**。再構築後も勝ち被写体ゼロ（全被写体 parity 以下）。
- HSV の理論的弱点は現行実装が既に構造的に回避している:
  - **Hue 特異点（S≈0）** → 低彩度では `chromaConfidence` で RGB 距離へフォールバック（`ColorZone.Match.cs:343`）、低彩度**サンプル**では純 RGB のグレーモードへ切替（`:205-256`）。OkLab の「特異点なし」という利点の大半をこの 2 段が先に吸収している。
  - **暗部の H/S ノイズ** → V に応じた確信度減衰（`:88-90`）とグレーモード適用域の動的拡大（`:203-205`）。
  - **HSV 距離の非知覚性**（同じ tolerance でも色相により知覚範囲が違う）→ 自動調整が tolerance を知覚量からでなく**実マッチ距離の分布**から導出する（`ZoneAutoTuner.Tolerance.cs`）ため、マッチ空間内で自己完結し、知覚均一性を必要としない。

つまり選択側は「素の HSV が優れている」のではなく、**HSV の不変量を核に、弱点を RGB フォールバックと統計的導出で潰したハイブリッド**として正当、が正確な評価である。

## 5. なぜ「再着色= OkLab」が正当か

再着色は合成問題であり、求められるのは「**色相・彩度を差し替えつつ、明度・陰影構造の*見え*を保つ**」こと。ここでは §3.2 の知覚均一性が本質要件になり、選択で有利だった HSV の性質はむしろ害になる:

- HSV 時代の実害（記録済み）: V/S 保持で色相だけ変えると、変換先色の輝度応答の違いで単調な明度 falloff が非単調化し、**リング（ドーナツ）・白部サイズ変化・ベタ塗り**が発生した（`PixelProcessor.ColorSpace.cs:17-21`、移行コミット f69e423）。
- OkLab 中核の設計は知覚空間の性質を直接利用する:
  - **L の 2 区間線形リマップ**（`PixelProcessor.Recolor.cs:213-216`）: [0,sL]→[0,tL], [sL,1]→[tL,1]。単調（＝知覚明度の順序保存＝リングの構造的排除）・端点保存（黒→黒/白→白）・不動点 sL→tL で base を target 明度へ寄せる（L 完全保持は暗色→黄で brown 化するため意図的に保持しない）。
  - **彩度は「大きさ＝元 chroma に比例、向き＝target 色相に均一化」**（`:200-212`）: §3.1 で見た「C は陰影で縮む」性質が、ここでは**望ましい転写特性**として働く——影で自然に脱彩した画素は、変換後も比例して脱彩する。選択で害だった同じ性質が、合成では利得になる（同一性質の符号が問題側で反転する良い例）。
  - 数学的正しさは `image_processing_math_review_2026-06-10.md` で全桁検証済み（変換行列・伝達関数が Björn Ottosson リファレンスと一致）。
- コスト面: cbrt×3/画素は LUT（`PixelProcessor.ColorSpace.cs:30-75`）で実用域に収めてあり、性能上の反証にならない。

なお、再着色側でも**不変量が必要な副問題**（アンカー推定 = 「パーツの地色」を陰影レベル非依存に見つける）では、OkLab 内の陰影不変量 **C/L** を使っている（`PixelProcessor.Recolor.cs:31-33` のコメント: 「C/L は乗算シェーディング不変」）。これは「判定には不変量・合成には知覚量」という原則が空間の内側でも一貫して適用されている証左で、本レビューの結論を補強する。

## 6. 留意点 — 正当だが無料ではない

分業の妥当性を認めた上で、単純図式（選択= HSV / 再着色= OkLab）からの逸脱と構造的コストを記録する。いずれも現状は妥当と判断するが、将来の変更時に「知らずに壊す」ことを防ぐため明文化する。

1. **再着色側への HSV/RGB の意図的な漏れ**:
   - 暗部脱彩のゲートは OkLab L でなく HSV V（`oV`, `PixelProcessor.Recolor.cs:250-256`）。旧 shadowDesaturation との挙動互換のためで、ゲート（発動条件）にのみ使われ色の計算には使われない。
   - ハイライト wash は RGB 空間の軸射影（`:282-322`）。「sample→白の直線」への射影は RGB でこそ直線になる（OkLab では白への経路は曲線）ため、これは RGB が正しい。
   - デコンタミの α 分解も RGB（混色 `α·FG+(1−α)·BG` はエンコード RGB 上の線形合成として起きているため）。
   - → いずれも「その副問題の物理が住んでいる空間で解く」という一貫した理由があり、無秩序な混在ではない。
2. **2 系の結合はスカラー橋のみ＝境界品質は選択側のソフトランプに依存**: 再着色は strength を通してしか選択を知らないため、選択が二値的だと AA 縁の情報が落ち、デコンタミの前提が崩れる。グレーモードの AA ソフトランプ（`AchromaEdgeSoftness`、`ColorZone.Match.cs:242-246`）はこの橋の帯域を保つための処置であり、削ると再着色側の縁品質が壊れる。
3. **マッチ空間の距離・tolerance は知覚量ではない**: tolerance 0.14（`CoreMatchDistance`）等の定数はマッチ空間内でのみ意味を持つ。ユーザー向け UI やドキュメントで「知覚的な近さ」として説明しないこと。自動調整が実距離分布から導出する設計（§4）を維持する限り問題にならない。
4. **S≈0 近傍の原理的退化は残る**: 純白は Hue が退化し彩度もほぼ 0 のため、淡い有彩（淡赤など）と HSV/RGB どちらの距離でも完全分離できないケースが既知（RejectNeutralForAchromaTarget の残課題として記録済み）。これは HSV 選択の欠陥ではなく極座標系共通の限界で、OkLab 化しても解けない（C≈0 で同型に退化する）。
5. **色距離そのものの上限**: 同色相・同彩度で明度だけ違う別パーツ（navy 問題）は、陰影不変量を使う限り**どの色空間でも原理的に分離不能**（不変量が同じ値を返すことこそが設計意図なので）。次の伸びしろは色でなく空間・構造の軸（flood-fill／マスク／シード）にある（`oklab_matching_conclusion.md` §5.1、Track C 記録）。

## 7. 代替構成を採らない理由（要約）

| 代替案 | 判定 | 根拠 |
|---|---|---|
| 選択も OkLab に統一 | **不採用確定（実測済み）** | 絶対 chroma が陰影で縮み recall 崩壊。修正= C/L 導入は HSV S の再構築に等しく、正味利得が消える。全被写体で勝ちゼロ。`oklab_matching_conclusion.md` |
| 再着色も HSV に統一（戻す） | **不採用（歴史的失敗）** | V/S の非知覚性でリング・brown 化・ベタ塗り。f69e423 で移行済み、戻さない方針が記録済み |
| CIELAB / CIECAM16 / HSLuv 等への差し替え | 不採用 | Lab/CAM 系の chroma は全て絶対量で OKLab と同型の陰影崩壊が効く（選択側）。再着色側では OkLab に対する優位が漸進的でコスト増のみ。「色距離の差し替え方向は実質打ち止め」が実験の確定事項 |
| 反射率×陰影の真の分離（intrinsic decomposition） | 研究・保留 | 理論上限としては正しいが、照明 GT 無しの手描き低解像度テクスチャには過剰でブリトル。`recolor_design_rationale.md` Tier 3 |

## 8. 再訪条件

本レビューは「現状維持を積極的に選ぶ」記録であり、恒久の禁止ではない。再検討に値する条件は `oklab_matching_conclusion.md` §5 と同一:

- 現行 HSV 選択が明確に失敗する未知テクスチャの実例が出る。
- 何らかの色空間が parity でなく、ある被写体で現行を**有意に上回る**証拠が出る。
- それまでは、色空間の統一・差し替え提案を改善サイクルの候補に載せない（同じ検討を繰り返さない）。
