# マニュアル

いろかのマニュアルは、原稿から組み立てた HTML（ページ 1 枚と、そこから読む CSS・JS・書体・画像・動画）を
オンライン版だけで配る。外部 CDN もフォントの取得もしない（どれも同じフォルダに入る）。
例外は表紙の紹介動画（YouTube）だけで、再生を押すまでは手元のサムネイルを出し、YouTube には繋がない
（押すと `manual.js` が youtube-nocookie.com の埋め込みに差し替える。動画の ID とサムネイルは `build_manual.py` の `INTRO_VIDEO_*`）。

- オンライン版: <https://yukkuri-aoba.github.io/Iroca/manual/>（`scripts/pages/build_site.py` が原稿から作って Pages へ）。
  いろかウィンドウ上部の「マニュアル」はこれを開く（`Code/UI/IrocaManual.cs`）。
- パッケージには入れない（2026-10-11 に決めた）。手元に古い版が残らず、いつも最新の説明が開く。
  その代わり、入れている版より新しい説明になることがある。
- 以前は同梱するつもりで、どこへ置いても壊れないよう全部を 1 枚の HTML に埋め込んでいた（約 4.8 MB）。
  オンライン版だけにしたので分けた（2026-10-11）。ページは約 140 KB で、画像は見える所まで来たら、
  動画は再生するときに読み、2 回目からはブラウザの写しを使う。

生成物はリポジトリに入れない（素材の写しが入るので、作り直すたびに履歴が膨らむため）。原稿と素材だけを追跡する。

## 中身

| パス | 役割 |
|---|---|
| `src/ja/NN-<章ID>.html` | 原稿。章ごとの HTML 断片（日本語） |
| `src/en/` | 英語版の原稿（日本語版が仕上がってから足す。フォルダに章があれば自動で言語切替が出る） |
| `src/page.html` | ページの外枠（ヘッダー・目次・フッター） |
| `src/manual.css` `src/manual.js` | 見た目と、目次・検索・言語切替・実演・動画 |
| `src/demos.json` | スライダー実演の定義（コマ画像と日英の文言） |
| `img/ui/*.webp` | Unity Editor の実ウィンドウのスクリーンショット |
| `img/demo/*.webp` | 実 C# エンジンの出力（実演のコマ） |
| `img/promo/intro-video.webp` | 表紙の紹介動画のサムネイル（動画の最後の画面 `dev_safe/promo/booth_new_lavender2/out/end-1920x1080.png` を 1280×720 に縮めたもの）。README の冒頭も同じ画像を使う |
| `clips/*.mp4` | 操作の短い動画 |
| `fonts/` | 書体 Noto Sans JP を原稿の字だけに絞り、太さを固めた WOFF2（本文 500・見出し 700）と、収めた字の一覧 `chars.txt`・`OFL.txt` |
| `build_manual.py` | 原稿 → `dist/`（標準ライブラリだけで動く） |
| `build_fonts.py` | `fonts/` を作る（fontTools と brotli が要る） |
| `build_assets.py` | スクリーンショットの切り出しと、実演コマの再着色 |

## 作り直す

```powershell
# 原稿を直したとき（docs/manual/dist/ ができる。index.html をダブルクリックで確認）
.venv\Scripts\python.exe docs/manual/build_manual.py

# 原稿に新しい漢字を足して build_manual.py が「フォントの部分集合にありません」で止まったとき
.venv\Scripts\python.exe -m pip install fonttools brotli   # 初回だけ
.venv\Scripts\python.exe docs/manual/build_fonts.py

# 実演のコマも作り直すとき（dev_safe と .NET SDK が要る）
.venv\Scripts\python.exe docs/manual/build_assets.py
```

`dist/` の中身:

| パス | 中身 |
|---|---|
| `index.html` | ページ（全章の本文・目次と検索のデータ） |
| `manual.css` | `src/manual.css` の頭に書体の指定（`@font-face`）を足したもの |
| `manual.js` | `src/manual.js` そのまま |
| `fonts/` `img/` `clips/` | 原稿が参照する素材だけの写し（参照していない素材は載らない） |

- 出力先は毎回作り直す（消した素材が残らないように）。ただし、このスクリプトが前に出力したフォルダか、
  空のフォルダにしか書かない（ページの `<meta name="generator">` で見分ける。別のフォルダを消さないように）。
- CSS・JS・素材の URL には中身のハッシュを付ける（`manual.css?v=…`）。Pages は 10 分ほどブラウザに写しを
  持たせるので、作り直した直後でも新しいページに古い CSS や画像が混ざらない。
- 同じ原稿からは毎回同じバイト列が出る（作り直しても差分が出ないように）。

## 見た目

宣伝画像（`dev_safe/promo/booth_new_lavender2`）と紹介動画に揃える。決まりは `dev_safe/promo/DESIGN.md`。
2026-10-17 に宣伝画像のデザインを変えたのに合わせて、地の色と書体を替えた（それまでは紙の地・Zen Maru Gothic。
2026-10-11 より前の暗い地に橙の差し色は、世界観が違うとして作り直した）。

- 薄紫の地（`#e9e9fa`、宣伝画像の地と同じ）に墨の文字（`#1d1d1f`）。実演の台は、宣伝画像の写真の台紙と同じ紙の色
  （`#f7f6f4`）。差し色は使わず、色は図版の中のものだけ。暗い側の地は、同じ色味を暗くした `#13131a`。
- 明暗は OS の設定（`prefers-color-scheme`）に従い、開いている間に OS 側が変わっても追従する（2026-10-11 から。
  それまでは明るい方に固定）。右上の切り替えで OS と逆にしたときだけその選択を覚え、OS と同じ側へ戻すと
  覚えた選択を消して、また OS に従う。最初の明暗は `page.html` の `<head>` で描く前に当てる（ちらつかない）。
- 書体は宣伝画像・字幕と同じ **Noto Sans JP**。配布元は太さを変えられる 1 ファイルなので、`build_fonts.py` が原稿の字だけに
  絞ってから本文と見出しの太さに固める。仮名の詰め（palt）は、書体にもとからあるものを外し、宣伝画像と同じ規則
  （仮名と約物は字面の幅＋0.1 字、句読点の後ろは 0.3 字空ける、漢字は 0.03 字詰める）のものに置き換えて、CSS で有効にしている。
- 表紙の「いろか」はふつうの字間（字間を広く空けた小見出しはやめた）。章番号と表の頭は字間を空けた灰色、章の頭と表の頭に
  墨の太い罫。影・ぼかし・グラデーションは使わない。手順の番号は、いろかのウィンドウの ①②③ と同じ丸囲み。

## 原稿の書き方

- 1 ファイル = 1 章。ファイル名 `NN-<章ID>.html` の `NN` が並び順、`<章ID>` がアンカー
  （`#install` など）。先頭に `<h2>章の見出し</h2>` を置く。
- `<h3>` には必ず `id` を付ける（目次に出る）。`<h4>` は任意。id は日英で共有するので、
  英語版でも同じ id にする（違うとビルドが止まる）。リンク `href="#…"` の先が無くても止まる。
- 本文はふつうの HTML（`p` `ul` `ol` `table` `blockquote` `code` `strong`）。`ol` は丸数字の手順になる。
- 図版と動画はカスタムタグで書く。ビルドが素材を `dist/` へ写し、寸法を入れる（無い素材を指すと止まる）。

```html
<x-shot src="img/ui/window.webp" wide>キャプション</x-shot>      <!-- スクリーンショット（クリックで拡大） -->
<x-demo id="tolerance"></x-demo>                                  <!-- src/demos.json の実演 -->
<x-before-after before="img/demo/src.webp" after="img/demo/color-red.webp">案内</x-before-after>
<x-clip src="clips/eyedropper.mp4" poster="clips/eyedropper.webp">キャプション</x-clip>  <!-- 動画 -->
```

- 同じ説明は 1 か所だけに書き、ほかの章からはリンクする（2026-09-21 に文字数を 36% 減らした方針）。
- 英語版は、日本語版が仕上がってから `src/en/` に同じファイル名・同じ id で足す。

## 動画

画面に入ったときだけ再生し（音なし・ループ）、外れたら止まる。`preload="none"` なので、再生するまで読み込まない。

- 1 本 5〜15 秒、操作 1 つ。長い通しの動画は作らない（UI が変わったら撮り直すのは 1 本で済むように）。
- 字幕は動画に焼き込まず、キャプション（HTML の文）に書く。日英で同じ動画を使え、言い回しを
  直すたびに撮り直さずに済む。
- 形式は MP4（H.264・yuv420p・CRF 24・30fps・音なし）。GIF は 256 色で陰影が縞になるので使わない。
  画面の録画はよく縮み、1 本 5〜15 秒で 100〜200 KB、いろかと Scene を並べた全幅のもので 300〜650 KB。
  2026-10-18 時点で 11 本・約 3.1 MB、マニュアル全体（`dist/`）で約 4.2 MB（書体 2 太さの約 0.35 MB を含む）。
- UI の文字を潰さないよう、`wide` を付けた動画は本文の幅を越えて元の大きさまで広がる（本文の箱 `main` の幅まで。
  画面の幅で決めていた頃は、広い画面で本文の列が中央に寄ると左の目次にかぶった）。
  録画から UI を縮めずに切り出す（いろかの窓なら幅 1024 px）。
- 撮影は実際の画面を録る（右クリックメニューやカラーピッカーは別窓なので）。道具と手順は
  `dev_safe/scripts/manual_clips/README.md`。

## 実演コマの作り方

**製品 C# が唯一の正**なので、コマ画像は headless ハーネス経由の実出力を使う
（`docs/testing-architecture.md`）。被写体は販促素材と同じ HAOLAN スニーカーの青。

- **実演の既定の変更先は純赤 (255,0,0) で固定**、スポイト位置はトゲの明るい青。どちらも作者プリセット
  `HAOLAN_Sneakers_Red`（`dev_safe/preset_samples/`）と同じ。朱など別の赤に変えると販促の赤と食い違う。
  色見本のほかの色は一般的な色名（オレンジ・黄・緑…）で出す。**和名・伝統色名は使わない**。

- **色見本・変更前後・模様保持・出力彩度**は、製品のワンショット経路（スポイト位置の AI マスク提案を
  証拠にした自動調整）で出す。**証拠なしの `--autotune` で作らないこと** — ハイライトの芯が青く
  取り残される。模様保持と出力彩度は、自動調整の導出値を土台に 1 項目だけ動かす
  （再現が自動調整の出力と一致することを `build_assets.py` が毎回確かめる）。
- **許容範囲だけは素のゾーン**（自動調整なし）で振る。自動調整後は保護が入り、許容範囲を上げても
  ほぼはみ出さないため、スライダーの効き方が画にならない。
- 模様保持は 0.75 未満を出さない（純赤だと 0.5 でもハイライトが灰色がかる。0 付近は芯が灰色に沈む）。
  純赤では自動調整が模様保持を 0.9 に下げるので、再現ゾーンも導出値を使う（1.0 固定だと再現がずれる）。
- 切り出しは左上のトゲ周辺。右隣の淡いラベンダーの UV にじみ（既知の残り）は枠に入れない。
- **出したコマは必ず等倍で目視する。** 変換漏れ（青い点）・元に無いノイズ・対象外の変色が無いこと。

## スクリーンショットの撮り直し

原板は `dev_safe/manual_shots/*.png`。撮影は Unity を起動したまま行う
（手順とスクリプトは `dev_safe/scripts/unity_ui_shot/README.md`）。

- 撮影中だけ `Code/Debug/IrocaEditor.Debug.asmdef` の `defineConstraints` にダミーを入れて
  Debug 衛星アセンブリを落とす。**配布物に Code/Debug は含まれない**ので、
  入れたまま撮ると出荷物に無い「パフォーマンス」セクションが写り込む。
  撮り終えたら必ず空配列へ戻す。
- プレビューが写る画（全体・プレビュー・前後比較・差分）は、自動調整の導出値を入れた状態で撮る
  （素のゾーンだと黒いアッパーに点が乗る）。詳細設定・加工設定の画だけは製品既定に揃える
  （マニュアル本文の既定値表と食い違わせない）。
- 前後比較は窓を 1320pt 幅に広げて撮る（800pt だと「変更後」側が切れる）。
- 切り出し範囲は `build_assets.py` の `SHOTS`。原板の座標は pixelsPerPoint 1.25 の実ピクセル。
