# BOOTH 商品編集画面：「段落」「埋め込みコンテンツ」仕様メモ

調査日: 2026-10-08
対象画面: `https://manage.booth.pm/items/{item_id}/edit`（商品情報を編集）
調査方法: 実際の編集画面の UI・DOM を観察（保存操作はしていない）

> 注意: BOOTH 公式の仕様書ではなく、画面から読み取った内容です。クラス名などは予告なく変わる可能性があります。

---

## 1. 「商品紹介文」セクションの全体構成

上から順に次の要素が並ぶ。

| 順 | 要素 | 種類 | 備考 |
|---|---|---|---|
| 1 | 見出し「商品紹介文」＋説明文 | テキスト | 「埋め込みコンテンツでYouTube動画を埋め込むと、一部ページの商品画像の先頭にもその動画が表示される」と案内あり |
| 2 | メイン本文（description） | `<textarea>` 1つ | プレースホルダー: `1.【動画】などは下の「埋め込みコンテンツ」で。` / `2.【長文】は下の「段落」機能で。` |
| 3 | 追加ブロックのリスト | `<ul>` 内に `<li>` が並ぶ | 「段落」と「埋め込みコンテンツ」が混在して並ぶ（追加順） |
| 4 | 「ソフトウェア用の推奨項目* を入力する」ボタン | `<button>` | `* サンプル動画、動作環境、アップデート履歴など…`。カテゴリが「ソフトウェア」のときに表示されるテンプレート挿入ボタン（中身は未検証） |
| 5 | 「＋ 段落」ボタン | `<button>` | クリックでリスト末尾に段落ブロックを追加 |
| 6 | 「＋ 埋め込みコンテンツ」ボタン | `<button>` | クリックでリスト末尾に埋め込みブロックを追加 |

- 「商品紹介文」（メイン本文）が空だと公開できない（画面下部に「公開するには『商品紹介文』を入力してください」と表示される）。
- 文字数上限は `maxlength` 属性では設定されていない（textarea / input とも `maxLength = -1`）。サーバー側の上限は未確認。

## 2. 段落ブロック

### 見た目

```
┌ 段落 ───────────────────── ×削除 ┐   ← ヘッダー（ドラッグで並べ替え）
│ 見出しテキスト   [ input type=text ]   │
│ 本文テキスト     [ textarea（複数行）] │
└──────────────────────────────┘
```

### フィールド

| 項目 | 要素 | ラベル(label text) | 備考 |
|---|---|---|---|
| 見出しテキスト | `<input type="text">` | `title` | 1行。プレースホルダーなし |
| 本文テキスト | `<textarea>` | `content` | 複数行。改行可 |

### 操作

- **並べ替え**: ヘッダー部分は `<button>`（class に `variation-box-head`, `cursor-grab`）。ドラッグ＆ドロップでブロック順を入れ替える方式。上下矢印ボタンはない。
- **削除**: ヘッダー右上の「×削除」ボタン（ホバー時に表示）。確認ダイアログは出ず即座に消える（未保存状態の場合）。
- 段落の数に上限があるかは未確認。

## 3. 埋め込みコンテンツブロック

### 見た目

```
┌ 埋め込みコンテンツ ───────────── ×削除 ┐
│ 埋め込みコード  [ input type=text ]       │
│                それぞれのサービスで提供されている │
│                埋め込み用コードを入力してください。│
│                ┃ 対応サービス: ...                 │
└──────────────────────────────┘
```

### フィールド

| 項目 | 要素 | 備考 |
|---|---|---|
| 埋め込みコード | `<input type="text">`（**1行**） | プレースホルダーなし。`<iframe ...>` などのHTMLを1行で貼る想定 |

### 対応サービス（画面表記そのまま）

- VRoid Hub
- Vimeo
- YouTube
- SoundCloud
- Bandcamp
- Google Maps
- SlideShare
- Sketchfab
- ニコニコ動画（『動画情報とサムネイル埋め込みコード』のみ）

### 仕様上のポイント

- URLではなく **各サービスが発行する埋め込み用コード（iframe等）** を入れる。
- YouTube を埋め込むと、一部ページで商品画像の先頭にもその動画が表示される。
- 対応外サービスのコードや不正なコードを入れたときの挙動（保存時エラー／表示されない等）は未検証。
- 操作（ドラッグ並べ替え・×削除）は段落ブロックと同じ。

---

## 4. 保存

- 画面最下部の「下書きで保存する」「公開で保存する」で、商品紹介文・段落・埋め込みを含むフォーム全体が保存される。
- ブロックの追加・削除・入力は保存ボタンを押すまで反映されない（※商品画像だけは即時反映）。

---

## 5. 自動入力・拡張機能を作る場合の実装メモ

- 画面は React 系の SPA（UI ライブラリ `charcoal`：`charcoal-text-area-textarea`, `charcoal-text-field-input` など）。
  - `element.value = ...` を直接代入しても state に反映されない。ネイティブ setter を使って `input` イベントを発火させる:
    ```js
    function setReactValue(el, value) {
      const proto = el.tagName === 'TEXTAREA'
        ? HTMLTextAreaElement.prototype
        : HTMLInputElement.prototype;
      Object.getOwnPropertyDescriptor(proto, 'value').set.call(el, value);
      el.dispatchEvent(new Event('input', { bubbles: true }));
    }
    ```
- `name` 属性・`id` 属性は付いていない。要素の特定には以下が使える:
  - メイン本文: プレースホルダーに「埋め込みコンテンツ」を含む `textarea`
  - ブロック一覧: メイン本文の後にある `ul > li`
  - ブロック種別: `li` 先頭のヘッダーボタンのテキスト（`段落` / `埋め込みコンテンツ`）
  - 段落内: `input[type=text]`（見出し）と `textarea`（本文）
  - 埋め込み内: `input[type=text]`（埋め込みコード）
  - 追加ボタン: テキストが `段落` / `埋め込みコンテンツ` の `button`（「＋」はアイコン）
  - 削除ボタン: `li` 内でテキストに `削除` を含む `button`
- ブロック追加後は DOM が非同期に更新されるため、追加ボタンのクリック後に新しい `li` が現れるのを待ってから値を入れる（MutationObserver や短いポーリング）。
- ボタンはすべて `type="submit"` 扱いで出力されているが、クリックしてもフォーム送信はされない（JS でハンドリング）。

### データモデル案（テンプレート保存用）

```ts
type DescriptionBlock =
  | { type: 'paragraph'; title: string; content: string }
  | { type: 'embed'; code: string };

interface DescriptionTemplate {
  description: string;          // メイン本文（必須）
  blocks: DescriptionBlock[];   // 表示順
}
```
