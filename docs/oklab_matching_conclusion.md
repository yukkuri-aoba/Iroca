# OKLab 選択距離 実験の結論 — なぜ選択は HSV+RGB ハイブリッドが正しいか

状態: **実験完了・不採用確定（2026-07-04）。実験コードは破棄済み（§6）。** 本番デフォルトは HSV+RGB ハイブリッドのまま。
背景・仮説・実装手順・初期計測を記した計画ドキュメント（`oklab_matching_distance_experiment_plan.md` / `oklab_matching_implementation_plan.md`）は実験破棄に伴い削除した。必要なら git 履歴（実装コミット `bd64c12`〜`d110de6` とその revert）から辿れる。

本書は、実験 I（絶対 chroma）〜 II（明度正規化彩度による再較正）の計測結果と、そこから固まった**現行 HSV+RGB ハイブリッドの正当性**を機構レベルで独立記録する。目的は「現行が優れているなら、その理由を証拠付きで固める」こと。**実験コードを消しても、この理由は残す**（同じ検討を繰り返さないため）。

---

## 1. 結論（TL;DR）

- OKLab ベースの選択（マッチング）距離は **不採用**。既定は従来 HSV のまま（golden 18 pass＝出力バイト不変）。
- 事前登録した採用ライン（①costume recall 回復 ②false_positive 非悪化 ③どこか 1 被写体で HSV に対する実勝ち、の**3条件同時**）のうち、**③が原理的に達成不能**だった。全被写体で OKLab は **良くて parity・勝ちゼロ**。
- 崩壊の機構と、それを修正するには「HSV の S の比率性を OKLab 上に作り直す」しかないことが実証され、**OKLab の正味の利得がこのドメインでは消える**ことが分かった。これが現行を HSV に据える積極的な理由になる。

## 3. 機構分析 — なぜ OKLab は崩れ、なぜ HSV が正しいか

### 3.1 崩壊の根本原因: OKLab 絶対 chroma は飽和色の陰影で縮む

HSV の彩度 `S = (max−min)/max` は**明度比率**である。飽和材質（例: 濃紺の衣装）を陰影で暗くしても（V が下がっても）、**S は ≈1.0 を保つ**。

一方 OKLab の chroma `C = √(a²+b²)` は**絶対量**である。線形 RGB を係数 f（<1）で暗くすると、LMS が f 倍→その立方根 l',m',s' が f^(1/3) 倍→L も a,b も（それらの線形結合なので）**ともに f^(1/3) 倍**になる。つまり **C は陰影で L と一緒に縮む**。

選択距離 `distOklab` の chroma 差項 `|C_pixel − C_sample|` と、彩度ゲート `C_pixel ≥ satMin` は、この縮んだ陰影 chroma を「サンプルと別素材」と誤判定する。結果、**飽和青の深い影が丸ごと選択から漏れる**（costume recall 0.609）。

### 3.2 このドメインは崩壊が最も刺さる形をしている

VRChat アバターのテクスチャは「**飽和したベース色 + 手描きの V（明度）シェーディング**」が支配的なスタイルである。3.1 の崩壊は、まさにこの**中心ユースケースを直撃**する。sneakers も同型（飽和青・V シェーディング）で、程度は軽いが同じ劣化方向を示した。

### 3.3 修正は「HSV の S を OKLab 上に作り直す」ことに等しい

C1/C1b の修正は、各画素の chroma を「サンプル明度ならいくつか」へ持ち上げる明度正規化彩度 `Sat = C / L`（陰影方向のみ、`ColorZone.MatchOklab.cs` の `pSat`）を使う。3.1 の性質より **C/L は線形暗化に対して厳密に不変**なので、同素材の陰影は `Sat ≈ Sat_sample` となり距離・ゲートで罰されなくなる。recall が復活したのはこの原理による。

しかし `Sat = C/L` は**HSV の S（比率彩度）を OKLab 空間上に再構築したものに他ならない**。つまり:

- 崩壊を防ぐには、HSV が最初から持っている「比率性」を後付けで足す必要がある。
- それを足した後に OKLab に残る正味の利得は「**知覚均一な色相角と明度**」だけに縮む。
- しかもその利得は、**現行 HSV+RGB ハイブリッドが低彩度で RGB ユークリッド距離へフォールバックする**ことで既に大部分回避済み（Hue 特異点の最悪部は現行が既に踏んでいない）。上乗せは漸進的。

### 3.4 同族トレードオフ: 単純な再構築では HSV の balance を超えられない

C1b では、costume（飽和青）の陰影を救うリフトが、**同じ飽和青の sneakers を過選択**させ precision を 0.992→0.970 に落とした。`Lfloor` を上げれば sneakers precision は戻るが costume recall が再び落ちる、**直接のトレードオフ**である。同一材質タイプなのに片方を直すと片方が悪化する——これは「1 ケース改善で他ケース悪化」そのもので、**HSV 式が多数の改善サイクルで到達した balance を、素朴な OKLab 再構築では超えられない**ことを示す。

## 4. HSV+RGB ハイブリッドの設計優位（明文化）

現行の選択距離（`ColorZone.Match.cs`）が持つ、OKLab が容易に真似できない性質:

1. **S の比率性** — 飽和材質の V シェーディング（このドメインの支配的スタイル）に対して、陰影でも彩度指標が保たれ、素材同一性が崩れない。
2. **低彩度での RGB フォールバック** — `CalculateHybridDistance` が `Lerp(rgbDist, hsvDist, chromaConfidence)` で低彩度時に RGB 距離へ退避し、HSV Hue の特異点（彩度 0 で角度未定義）の最悪部を構造的に回避している。OKLab の「特異点なし」の利点の大半をこれが既に吸収している。
3. **非対称ヒューリスティックの蓄積** — 暗部/明部フォギブネスの意図的な非対称（暗部の距離短縮は巻き込み主因のため廃止・明部のみ温存）など、実テクスチャの失敗モードを 1 つずつ潰して収束させた balance。距離式の土台を替えると、これらが一斉にぶり返す。

## 5. 再訪する場合の条件

この実験は「現状維持」を積極的に選ぶ根拠であって、OKLab を永久に否定するものではない。次のいずれかが揃えば再検討に値する:

- 現行 HSV が**明確に失敗する未知テクスチャの実例**（現状、測定 4 被写体すべてで 0.99+ / costume 0.937 と完成域）。
- OKLab（または他の色空間）が parity でなく、**ある被写体で HSV を有意に上回る証拠**。
- それが無い限り、この結論（parity 止まり・移行コスト不合）を覆さない。**同じ検討を繰り返し起こさないこと。**

### 5.1 次の伸びしろは「色距離」ではなく「空間・構造」の軸にある

本実験が確定させたのは「**選択のボトルネックは色空間ではない**」ということでもある。色距離を差し替える方向（HSV↔OKLab↔CIELAB…）は、Lab 系すべてに同じ絶対 chroma 崩壊が効くため実質打ち止め。したがって**今後の改善リソースを色距離いじりに使うのは非効率**。

現行が原理的に解けない最難関——**同色相・同彩度で明度だけ違う別パーツ（例: 濃紺 navy の別マテリアル）**——は、色距離である限り HSV でも OKLab でも分離不能。ここを超える道は色ではなく、**連結成分（flood-fill・既に稼働）／マスク／シード**という空間・構造の軸にある。ただしシード統合は過去に頓挫しており（tolerance 再走と非同期化の両立が必要）、着手するなら狙う失敗ケースを GT で先に固めること。

## 6. 実験コードの扱い（破棄済み）

本結論（不採用）を受けて、OKLab 選択距離の実装・配線・デバッグトグル・計器フラグ・計画 doc は**コードベースから破棄した**（実装コミット `bd64c12`〜`d110de6` を revert）。既定の HSV 経路はバイト不変のまま（golden 18 pass・選択キー監査 pass）。

- 破棄したもの: `Code/Core/ColorZone.MatchOklab.cs`、`DebugCaptureHooks.MatchDistanceOklab` と `PixelProcessor` の分岐、`ColorZone.cs` の OKLab 派生キャッシュ、Harness `--matchDistance`、PerfView トグル、visual_review の `--match-distance`、OKLab 計画 doc 2 本。
- 影響なし（元から HSV / OkLab）: 再着色本体（`RecolorPixel` は引き続き OkLab 発色）、`ZoneAutoTuner`（自動調整）、緩和経路（穴埋め/境界回復）。
- 再現したい場合: 上記コミット範囲を git 履歴から復元すれば隔離実験経路を再構築できる。計測計器は dev_safe（別リポ）の `_oklab_ab.py`。
